Overview

How much tool output Kompactor shortened before Claude read it, and what that saved you.

What do these numbers mean?
Tokens saved
Tool output Claude would have read in full (command results, files it opened), minus what Kompactor handed it instead. Failures, errors and the code Claude needs are always kept.
Worth
What those tokens would have cost on the Claude API at the price of the model each session ran on: once when first sent, then again on every later request in the session that would have re-read them, until the conversation was compacted. On a Pro or Max plan it shows the value, not money off your bill.
Output shortened
How much smaller the tool output was, all together, after Kompactor trimmed it.
Replies
Each time Claude finished answering you. A reply was helped when Kompactor shortened at least one output in it.

Configuration

Choose how hard Kompactor compacts. One level sets everything: toward detail, Claude sees more of the raw output; toward savings, less. Fine-tune any setting below.

What Kompactor does

Each technique saves tokens in a different place. Switch any of them off; for the ones that are on, the level sets how strong they are.

Advanced settings

Every setting the level controls, explained. Changing one overrides the level for it; "Reset" goes back to the level's value.

In Claude Code

How savings are shown. These don't depend on the level.

Show savings after each turn
A one-line summary after every Claude reply, such as "−8.2k tokens this turn".
Status line
Running savings in the Claude Code terminal status line. Never replaces a status line you already have.
Subagents that get the rules
A pattern matched against each subagent's type, e.g. explore|general. Empty means every subagent. Applies while "Apply rules to subagents" is on.
Keep history for
Savings history and stashed raw outputs older than this are deleted.
