Kompact guide · v0.3

Spend Claude Code's tokens on your code, not on noise

Kompact trims what Claude reads (test runs, installs, git output, whole-file reads) and how much it writes, and shows the saving after every turn. It works in the Claude Code CLI and the VS Code extension, on this machine only.

Install

Pick one. All three end in the same place, and you can change everything later from the dashboard.

VS CodeInstall the extension file, then click Enable when Kompact asks. The status bar starts showing savings. 
code --install-extension kompact-0.3.0.vsix
TerminalmacOS and Linux. Needs Python 3.9 or newer and nothing else. Opens the dashboard when done. 
git clone https://github.com/amarkum/Kompact
./Kompact/install.sh
Claude Code pluginFrom inside any Claude Code session. 
/plugin marketplace add amarkum/Kompact
/plugin install kompact@kompact

Windows: run .\Kompact\install.ps1 from a clone, or use the VS Code extension. The CLI and the VS Code extension read the same ~/.claude/settings.json, so one install covers both. A backup of that file is kept as settings.json.kompact-backup.

Setup adds hooks, a status line (if you don't have one) and, on macOS and Linux, Claude Code's CLAUDE_CODE_SHELL_PREFIX setting pointing at ~/.kompact/bin/kompact-shell, which is what lets Kompact compact failing commands. It never replaces a status line or shell prefix you already have. Restart open Claude Code sessions after setup.

Open the dashboard any time with kompact ui, or Kompact: Open Dashboard in VS Code.

What happens in a session

Kompact works through Claude Code hooks, so it acts on every tool call without Claude having to remember to use it. Your commands run exactly as typed; only what Claude reads changes.

Session starts
Short rulesAbout 150 tokens of reply rules for your level. The code graph is built or refreshed in the background.
Claude runs a command
Output is compactedPassing tests, progress bars, download chatter, library stack frames and lock-file diffs are removed. Errors, failures, your own frames and summaries stay. The full output is stashed and Claude is told how to get it.
A command fails, or prints a lot
Still compacted, still completeClaude Code cuts a failing command's output to its first and last few thousand characters, which usually drops the failures at the end of a test run, and it replaces very long output with a 2 KB preview. Kompact's shell prefix runs tests, builds, linters and installs to completion and hands Claude the failures and summary, with the exit code unchanged. Long outputs are compacted from Claude Code's saved copy.
Claude first searches or reads code
Code map, onceA budgeted map of the most depended-on modules (Balanced and up). Sessions that only run commands don't pay for it.
Claude opens a big file
Outline firstThe first full read of a large source file returns its outline with line ranges and who imports it. Claude then reads only the ranges it needs. Repeating the read returns the whole file.
Claude edits code
Graph refreshChanged files are re-indexed in the background, so later lookups see the new code.
A subagent starts
Same rulesSubagents get the same prose and code rules as the main agent.
Claude replies
Turn summaryThe saving for the turn appears in Claude Code, in the status line, in the VS Code status bar and on the dashboard.

Quality vs tokens

One level sets every option. Move toward quality and Claude sees more raw output; toward savings and it sees less. Every individual setting can still be changed on the dashboard, globally or per project.

LevelWhat Claude getsUse when
1 Max qualityAlmost everything. Only outputs over about 1,500 tokens are touched, and only pure noise is removed.Debugging something subtle, or auditing Kompact itself.
2 QualityNoisy commands compacted, passing tests hidden, one-line git log. Big files still read whole up to 800 lines.You want savings with no change to how Claude reads files.
3 BalancedOutline-first reads, library stack frames trimmed, a 500-token code map, lean code style.Default. Day-to-day work.
4 SavingsTighter caps, 3 lines of diff context, test banners dropped, shorter replies.Long sessions, big repos, tight budgets.
5 Max savingsMost aggressive caps, 1 line of diff context, telegraphic replies.Routine tasks where you mostly want results.

Changing the level

  • Dashboard: Quality vs tokens. The live preview shows exactly what Claude would get, with removed lines marked.
  • VS Code: click the Kompact item in the status bar, then Choose quality vs tokens level.
  • In Claude Code: type /kompact balanced, /kompact max savings and so on.
  • Terminal: kompact config preset 4, or kompact presets to list them.
Never shortened at any level: code, commands, file paths, error text, numbers, negations, security warnings, commit messages and docs.

Using it from chat

Kompact installs a small /kompact skill (about 370 tokens, loaded only when used).

TypeWhat Claude does
/kompactShows savings so far.
/kompact max savingsSwitches the level. Any level name or number works.
/kompact reviewReviews your current diff for code that could be cut: duplicates of existing helpers, options nobody asked for, dead branches.
/kompact auditLists dead-code candidates from the code graph and ranks what is safe to remove.
/kompact debtSummarises shortcut:, FIXME, HACK and TODO comments by severity.
/kompact graph <question>Finds code by topic, or shows what a change affects.

Code graph

Kompact indexes functions, classes, methods, imports and calls for Python, Go, TypeScript, JavaScript and React on this machine. Building it takes well under a second for most repos, and only changed files are re-parsed. It is stored outside your repo, so it never shows up in diffs.

# find code by topic
kompact graph query "session cookie signing"
# what breaks if this changes, and which tests to run
kompact graph impact src/flask/sessions.py
# one symbol: where, who uses it, what it uses, its tests
kompact graph explain Flask.make_response
# overview, dead code, import cycles
kompact graph report
kompact graph unused

You rarely need to type these. Claude gets the outline and the "imported by / tests" line automatically when it opens a big file, and the rules mention the commands in one line.

Projects and languages

Each repo's languages are detected from pyproject.toml or requirements.txt (Python), go.mod (Go), tsconfig.json or package.json (TypeScript) and a react or next dependency (React). The profile decides which stack frames are library noise, which files are generated, and which lock files collapse in diffs. You can pin languages on the dashboard instead.

Give a repo its own level under Projects & languages, for example Max quality for a payments service and Savings for everything else.

Getting the full output

  • Every compacted output ends with a note such as [kompact: 4210›612 tokens; full output: kompact show 17]. Claude, or you, can run kompact show 17, or kompact show 17 --lines 120-180 for a slice.
  • kompact search "TypeError" searches every stashed output.
  • To skip compaction for one command, start it with KOMPACT_RAW=1.
  • For commands you always want raw, add them to Never compact these commands on the dashboard.
  • An outline is never a dead end: repeating the same Read returns the whole file.

Proving it on your repo

kompact prove runs the same tasks through real headless Claude Code sessions with and without Kompact, and reports tokens, cost, turns and whether each answer was right. Write a few tasks that look like your team's work:

{ "tasks": [ {
    "id": "failing-tests", "repo": "api",
    "prompt": "Run the tests with `pytest -v` and tell me which fail and why.",
    "tools": ["Bash(pytest:*)", "Read", "Grep"],
    "max_turns": 8, "expect": ["test_refund_rounding"] } ] }
kompact prove --tasks my-tasks.json --repos ~/code --reps 3 --out evidence

Each run is capped at $1 by default (--budget). The report lands in evidence/REPORT.md.

Troubleshooting

Is it working?

Dashboard › Setup › Run self-test runs every installed hook exactly as Claude Code would and shows pass or fail with timings. From a terminal, use kompact doctor.

Claude can't run kompact

Installs from VS Code or a clone add a launcher at ~/.kompact/bin/kompact, which Claude can always call. Add ~/.kompact/bin to your PATH if you want to type kompact yourself.

Turn it off

Dashboard › Setup › Disable, or kompact install --uninstall. This removes the hooks, the status line and the shell prefix. Your other hooks and your own status line are never touched. To keep everything except the shell prefix, turn off Compact failing commands too on the dashboard or run kompact install --no-shell-prefix.

Every command fails with kompact-shell: not found

~/.kompact was deleted while Kompact was still set up. Remove the CLAUDE_CODE_SHELL_PREFIX line from ~/.claude/settings.json, or reinstall and run kompact install --uninstall. If Kompact itself is broken or removed but the script is still there, commands simply run untouched.

Where is my data?

In ~/.kompact: settings (config.json), the savings history and stashed outputs (kompact.db, pruned after 30 days by default) and code graphs (graphs/). Nothing is sent anywhere.

FAQ

Does it change what my commands do?

No. Commands run exactly as written, with your normal permissions: Claude Code checks Claude's command against your rules before Kompact is involved. Kompact only changes the text Claude reads afterwards. The one visible difference: for tests, builds, linters and installs, the shell prefix collects the output until the command finishes, so those lines don't stream live in the terminal. Servers, watch modes and every other command stream as usual, and the exit code is always the command's own.

Does it slow Claude Code down?

Each hook takes about 50 to 90 ms, far less than a model turn. The shell prefix adds about 50 ms to test, build and lint commands and nothing measurable to the rest. Code graphs build in under a second for most repos, in the background for big ones.

How is this different from graphify, ponytail or caveman?

Each of those covers one layer. Kompact covers command output, file reads, code navigation, reply length and code size together, acts automatically through hooks, keeps its own instructions small, and measures the result in real A/B sessions. The README has a feature-by-feature comparison.

Will Claude miss something important?

Errors, failing tests, your own stack frames and summaries are kept at every level, and the full output is always one command away. If in doubt, use a lower level for that project.
